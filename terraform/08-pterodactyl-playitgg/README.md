# Pterodactyl VM and Playit tunnel

This Terraform module provisions `vm-pterodactyl01` at `192.168.1.175` on the home LAN and `10.6.7.175` on the Proxmox SDN. Cloud-init installs the Docker runtime. `stack_pterodactyl.tf` manages the official Panel, MariaDB, Redis, and Wings containers; `stack_playitgg.tf` manages a dedicated Playit agent. The Panel is published on HTTP port 80 at `http://192.168.1.175`; access it through the LAN or Tailscale.

## Apply the game stack

The MariaDB passwords and Valheim join password are in the ignored `terraform.tfvars`. The first Pterodactyl administrator must already exist. On `terraform apply`, `stack_pterodactyl.tf` follows the existing Docker-stack SSH scaffolding pattern to create the location and node, reserve UDP allocations `2456` and `2457`, import the pinned Valheim egg, generate Wings configuration, and create the Valheim server. Wings starts after the generated config is installed; the Valheim install then runs from the Panel queue.

The VM has 8 GB RAM. Terraform gives the Valheim server 4 GB RAM, 25 GB disk, and 2 CPU cores, leaving capacity for the Panel and system. The server uses the Steam backend (`ENABLE_CROSSPLAY=0`) so its game ports can be carried over Playit UDP tunnels.

Keep the Panel, Wings API, and SFTP management ports off the public game tunnel. Use the LAN or existing Tailscale subnet route for Panel administration.

## Playit.gg

`playit_secret_key` must be the actual agent secret generated by Playit for this account and agent. A random password cannot enroll an agent. Set the account-issued secret in `terraform.tfvars`; the existing random placeholder makes the agent restart without connecting.

After the agent is online, create UDP tunnels for local ports `2456` and `2457` to `127.0.0.1` on `vm-pterodactyl01`. The Playit hostname/port is the public join address. Keep the Valheim join password private and share it with players separately.

## VM sizing and updates

The VM has 4 vCPU, 8 GB RAM, and a 50 GB disk as a starter allocation. Increase CPU, RAM, or disk to fit the game and expected player count. Cloud-init runs only on first boot; if this VM was already created, changing the cloud-init snippet will not rerun its provisioning automatically.
